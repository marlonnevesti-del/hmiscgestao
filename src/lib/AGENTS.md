- Surgical kit catalog (code, name, items) lives in surgical-kits.json/.ts; read-only, separate from dispensed prescriptions.
- Admin employee profile edits use adminUpdateEmployee (server-checked role; super_admin edits only by super_admin).
- UTI Neonatal records are NEO_FORMS entries on patient.intensive.neo; neoReport builds its monthly indicators.
- Ambulatory nursing pre-consult eligibility is needsNursingPreConsult in ambulatorio.ts (obstetric specialty or encounter/appointment nursingPreConsult flag).
- Admin open BAA/FIA management is /gestao-atendimentos (admin-only via canAccessPage); edits go through correctEncounter and admission reversal through revertAdmission (cancels FIA, reopens BAA, frees bed) in hospital-store, both with mandatory justification logged in history.
- Sidebar badges and home cockpit counts come from pendingCounts in dashboard.ts so menu and painel never disagree.
- OS cost report: src/lib/os-report.ts values movements by stock unitCost; /prestacao-contas shares faturamento area.
- SUS billing (BPA/AIH) rows, DATASUS pending-issue rules and positional export files live in src/lib/sus-billing.ts; /faturamento-sus shares the faturamento access area so admin area grants stay consistent.
- CME rules (kit status, autoclave cycles, validity, biological block, barcode) live in src/lib/cme.ts; kit use is registered on the surgery via registerCmeKitUse in hospital-store so traceability stays centralized.
- Controlled-cabinet items come from src/lib/controlled-catalog.json merged into the pharmacy stock (location "Armário de Controlados"); expiry status, lot map and monthly consumption/purchase suggestion rules live in src/lib/controlled.ts; dispensations log 'consumo' and expiry write-offs log 'vencimento' movements so the report reads one history.

- Physiotherapy requests ride on patient.physio (src/lib/physio.ts); doctors request from the medical assessment and /fisioterapia (shares the pacientes access area) records sessions that also append a Fisioterapia evolution, so no new snapshot keys are needed.
- Milk bank (BLH) rules (raw 15-day validity, Dornic/microbiology approval, crematocrit kcal, autonomy, AT46 report) live in src/lib/milk-bank.ts; data is the milkBank snapshot key because it is hospital-level stock, not per-patient; /banco-de-leite shares the enfermagem access area.
- Bed-board badges (allergy, MDR isolation, stay length, milk, physio) are derived in src/lib/bed-board.ts from existing patient data, so the census needs no new stored fields.
